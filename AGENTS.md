# Инженерные стандарты и правила проекта (AGENTS.md)

## 1. Стек и базовые требования
- Язык: Python 3.11+.
- Строгая типизация: все сигнатуры функций и методов обязаны содержать Type Hints (типы аргументов и возвращаемых значений).
- Работа с данными: все модели сущностей, входные и выходные форматы валидируются через `pydantic.BaseModel` (Pydantic v2).
- Настройки и секреты: считываются исключительно через `pydantic_settings.BaseSettings` из переменных окружения (`.env`).
- Работа с файлами и путями: использовать исключительно `pathlib.Path` с явным указанием `encoding='utf-8'`.

## 2. Архитектура слоев (Layered Architecture)
- `src/models.py`: Схемы данных, валидация типов, бизнес-ограничения. Никакой логики сохранения или бизнес-расчетов.
- `src/config.py`: Конфигурация окружения и безопасная загрузка параметров.
- `src/services.py`: Чистая бизнес-логика (парсинг, преобразование, математика). Без побочных эффектов.
- `src/main.py`: Точка входа. Читает настройки, запускает пайплайн из `services`, обрабатывает верхнеуровневые ошибки.
- `tests/`: Unit-тесты на базе `pytest`. Каждый этап разработки покрывается тестами до или параллельно с кодом.

## 3. Безопасность и санитария кода
- КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО хардкодить токены, пароли, логины и пути к базам данных прямо в коде.
- Никаких "голых" `except:` — только конкретные типы ошибок (`FileNotFoundError`, `ValueError`, `ValidationError`).
- Запрещены небезопасные вызовы системных команд через `os.system` или сборку небезопасных строк.
- Все пути проверяются на выход за пределы рабочей директории (защита от Path Traversal).

## 4. Протокол взаимодействия с ИИ
- Перед написанием кода выведи 1 короткое предложение с описанием плана.
- Любое добавление или изменение логики обязательно сопровождается unit-тестом в `tests/`.
- Не удаляй существующие docstrings и важные комментарии при рефакторинге.
- Актуализируй чек-лист в `TASK_STATE.md` после завершения каждого шага.
